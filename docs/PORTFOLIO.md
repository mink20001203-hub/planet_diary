# Planet Diary 포트폴리오 정리

## 프로젝트 개요

Planet Diary는 365일 동안 태양계를 여행한다는 스토리텔링을 기반으로 한 Flutter 웹 일기 앱입니다. 단순한 일기 작성 앱이 아니라, 날짜별 행성 구간, 감정 기록, 사진 기록, 퀘스트, 리캡, 업적 시스템을 결합해 사용자가 꾸준히 기록하도록 설계했습니다.

- 프로젝트명: Planet Diary
- 형태: Flutter Web App
- 배포 URL: https://mink20001203-hub.github.io/planet_diary/
- 저장 방식: Hive 로컬 저장소, 웹에서는 IndexedDB 기반
- 배포 방식: GitHub Actions + GitHub Pages

## 개발 목표

일기를 쓰는 행동을 게임처럼 느끼게 만드는 것이 핵심 목표였습니다. 사용자는 매일 하나의 행성 구간을 지나며 감정, 사진, 텍스트, 퀘스트를 기록하고, 월간/연간 리캡과 업적 배지를 통해 자신의 기록을 다시 확인할 수 있습니다.

## 핵심 구현 기능

### 1. 태양계 여행 맵

CustomPainter를 사용해 태양계 맵을 직접 구현했습니다. 궤도는 원이 아니라 기울어진 타원으로 표현했고, `sin(angle)` 값을 깊이로 사용해 행성의 크기, 밝기, 렌더링 순서를 조정했습니다. 추가 3D 패키지를 사용하지 않고 수학 계산만으로 입체감을 만들었습니다.

### 2. 날짜 기반 여행 시스템

사용자가 여행 시작일을 직접 설정할 수 있도록 했습니다. 시작일은 Hive settings box에 저장되며, 현재 날짜와 시작일의 차이로 `tripDay`를 계산합니다. 오늘 이후의 미래 날짜는 일기 작성이 불가능하도록 제한했습니다.

### 3. 일기 작성, 조회, 수정 흐름 분리

기존에는 일기를 다시 열면 바로 작성 화면으로 진입해 수정과 신규 작성의 경계가 불명확했습니다. 이를 조회 모드와 수정 모드로 분리해, 저장된 일기는 먼저 읽기 전용 화면으로 보여주고 사용자가 `EDIT`을 눌렀을 때만 수정하도록 개선했습니다.

### 4. 퀘스트와 XP 시스템

행성별로 다른 한글 퀘스트 3개를 제공하고, 일기 작성/사진 추가/퀘스트 완료에 따라 XP를 지급합니다. 기존 일기를 수정할 때 XP가 중복 지급되는 문제를 방지하기 위해 신규 저장 여부를 기준으로 보상 로직을 분리했습니다.

### 5. 월간/연간 리캡

월별 기록률, 감정 분포, 사진 하이라이트, 행성별 기록, 퀘스트 완료 수를 확인할 수 있는 월간 리캡 화면을 추가했습니다. 연간 리캡에서는 전체 365일 여행 기록을 요약해 사용자의 누적 데이터를 시각적으로 보여줍니다.

### 6. 백업/복원

Hive에 저장된 일기 데이터를 JSON 파일로 내보내고 다시 불러오는 기능을 구현했습니다. 웹에서는 조건부 import로 `dart:html` 기반 파일 다운로드/업로드를 처리해 브라우저 데이터 삭제나 기기 변경에 대비했습니다.

### 7. 업적/배지 시스템

첫 일기 작성, 7일 연속 기록, 사진 10장, 퀘스트 30개 완료 등 조건 기반 업적을 추가했습니다. 업적은 별도 저장값이 아니라 현재 일기 데이터에서 계산되므로 데이터 정합성이 높고, 월간/연간 리캡과 자연스럽게 연결됩니다.

## AI를 활용한 문제 해결 및 구현 능력

이 프로젝트는 AI를 단순 코드 생성 도구가 아니라 문제 분석과 구현 설계 도구로 활용한 사례입니다. 오류 로그, 화면 캡처, 요구사항을 바탕으로 문제를 쪼개고, 기능 단위로 구현 방향을 정리한 뒤 코드에 반영했습니다.

### AI 활용 사례

- Flutter 웹 실행 시 검은 화면만 출력되는 문제를 로그 기반으로 추적했습니다.
- Hive Adapter 생성 파일 누락으로 GitHub Actions 빌드가 실패한 문제를 해결했습니다.
- GitHub Pages 404 문제를 저장소 공개 여부와 Pages 설정 문제로 구분해 원인을 파악했습니다.
- 한글이 깨져 보이는 문제를 폰트 미지원 문제로 판단하고 한글 텍스트에 Noto Sans KR 또는 시스템 폰트를 적용했습니다.
- 일기 수정 시 XP가 중복 지급되는 문제를 기존 데이터 존재 여부로 분기해 해결했습니다.
- 날짜와 tripDay가 어긋나는 문제를 사용자 설정 시작일 기반 계산으로 수정했습니다.
- 추가 패키지 없이 CustomPainter 수학 기반 3D 태양계 표현을 구현했습니다.

## 작업 리스트 데이터

### 작업 1: Flutter 웹 일기 앱 구조 설계

- 사용 도구: ChatGPT, Codex, Flutter
- 수행 내용: 365일 태양계 여행이라는 콘셉트를 앱 구조로 분해하고, 화면 흐름을 태양계 맵, 캘린더, 일기, 리캡, 설정으로 구성했습니다.

- 사용 도구: ChatGPT, Flutter CustomPainter
- 수행 내용: AI에게 타원 궤도, 깊이값, 행성 크기/밝기 계산 방식을 프롬프트로 제공하고, 추가 패키지 없이 3D 느낌의 태양계 맵을 구현했습니다.

### 작업 3: Hive 기반 일기 데이터 저장

- 사용 도구: ChatGPT, Hive
- 수행 내용: 일기 텍스트, 감정, 사진 경로, 퀘스트 완료 상태를 Hive에 저장하고 웹에서는 IndexedDB 기반으로 데이터가 유지되도록 구성했습니다.

### 작업 4: GitHub Pages 배포 자동화

- 사용 도구: ChatGPT, GitHub Actions
- 수행 내용: Flutter 웹 빌드 명령과 `base-href` 설정을 정리하고, main 브랜치 push 시 GitHub Pages로 자동 배포되도록 워크플로를 구성했습니다.

### 작업 5: 오류 로그 기반 문제 해결

- 사용 도구: ChatGPT, GitHub Actions 로그
- 수행 내용: `diary_entry.g.dart` 누락, GitHub Pages 404, 폰트 깨짐, build/web 배포 문제를 로그와 화면 캡처 기반으로 분석해 수정했습니다.

### 작업 6: 리캡/백업/업적 고도화

- 사용 도구: ChatGPT, Riverpod, Hive
- 수행 내용: 월간 리캡, 연간 리캡, JSON 백업/복원, 업적 배지 시스템을 추가해 단순 일기 앱을 성장형 기록 앱으로 확장했습니다.

## 문제 해결 상세

### 문제 1: GitHub Pages 404

- 상황: 배포 Action은 성공했지만 접속 URL에서 404가 발생했습니다.
- 원인: GitHub Pages가 private repository에서 바로 활성화되지 않았고 Pages 설정이 필요했습니다.
- 해결: 저장소 공개 또는 Pages 사용 가능 플랜/설정이 필요함을 확인하고, 배포 URL과 base href를 `/planet_diary/`로 맞췄습니다.

### 문제 2: Web build 실패

- 상황: GitHub Actions에서 `DiaryEntryAdapter`를 찾을 수 없다는 오류가 발생했습니다.
- 원인: Hive generator로 생성되는 `diary_entry.g.dart` 파일이 누락되었습니다.
- 해결: 생성 파일을 반영하고 Hive Adapter 등록 흐름을 정상화했습니다.

### 문제 3: 한글 깨짐

- 상황: 화면의 한글이 이상한 문자로 표시되었습니다.
- 원인: Space Mono 폰트가 한글을 지원하지 않았습니다.
- 해결: 한글 텍스트에는 Noto Sans KR 또는 시스템 폰트를 사용하도록 분리했습니다.

### 문제 4: 중복 XP 지급

- 상황: 기존 일기를 다시 저장해도 퀘스트 XP를 반복 획득할 수 있었습니다.
- 원인: 신규 작성과 기존 수정 흐름이 분리되어 있지 않았습니다.
- 해결: `existing == null`일 때만 XP를 지급하도록 수정했습니다.

포트폴리오에는 아래 6장을 넣는 구성이 좋습니다.

- 2장: 캘린더와 날짜별 기록 상태
- 3장: 일기 조회/수정 화면

- 5장: 업적/배지 화면

## 테스트 방법

개발 중 빠른 점검은 아래 명령을 우선 사용합니다.

```powershell
flutter pub get
flutter test
git diff --check
```


